01 / AUTHENTICATION

Authentication

The currently documented endpoints do not require an API key or authentication header.

Base URL https://renpyflare.vercel.app/api/v1/
Authentication

Not required for the documented public routes.

Transport

HTTPS requests using standard HTTP methods.

02 / ENDPOINT

RyzenAPI

Retrieves the application file associated with a Steam AppID through the RyzenAPI upstream service.

GET /api/v1/ryzenapi/{appid}
Try endpoint

The endpoint validates the AppID and proxies the response from RyzenAPI. The returned content is binary and can be saved directly as a file.

Path parameters
Name Type Required Description
appid string YES Numeric Steam application ID.
Upstream request
upstream.txt 
https://api.ryzennetworking.duckdns.org/api/download/{appid}
!
Binary response The endpoint does not guarantee JSON. Depending on the upstream response, it returns a binary file while preserving the relevant content headers.
03 / ENDPOINT

SkyAPI

Route available through the same API base for SkyTools-related integrations.

GET /api/v1/skyapi/{appid}
Try endpoint

Use a numeric AppID in the route path. The exact response format depends on the implementation and upstream service connected to SkyAPI.

Path parameters
Name Type Required Description
appid string YES Numeric Steam application ID.
i
Implementation note SkyAPI is listed as an available route, but its complete response contract should be defined according to its current implementation.

use std::fs;
#[tokio::main]
async fn main() -> Result<(), Box> {
    let appid = 730;
    let url = format!(
        "https://renpyflare.vercel.app/api/v1/ryzenapi/{}",
        appid
    );
    let response = reqwest::get(url).await?;
    if !response.status().is_success() {
        return Err(format!("HTTP {}", response.status()).into());
    }
    let bytes = response.bytes().await?;
    fs::write(
        format!("manifest-{}.bin", appid),
        bytes
    )?;
    println!("Download complete");
    Ok(())
}

05 / RESPONSES

Response behavior

RyzenAPI forwards the upstream status when the external service returns an error and sends the downloaded content when successful.

200

Successful request. Returns the upstream binary content.

400

The AppID is missing or does not contain only numeric characters.

405

The request method is not GET.

502

The API could not connect to RyzenAPI.

Upstream

When the upstream responds with a non-success status, the same status is forwarded by the API.

06 / ERRORS

Error handling

Always validate the HTTP status before attempting to save or parse the response.

Invalid AppID

Use only numeric Steam AppIDs in the route parameter.

Network failure

Retry when a temporary upstream connection error occurs.

Binary handling

Use byte-oriented response handling instead of JSON parsing.
